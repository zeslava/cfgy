# Отчет о валидации дизайн-системы

## Дата проверки
Проверка выполнена на основе правил из `.cursor/rules/design_system_rules.mdc`

## Критические проблемы

### 1. Хардкодные hex-коды в компоненте Button

**Файл**: `web/src/components/ui/Button.tsx`

**Проблема**: Используются хардкодные hex-коды для hover/active состояний вместо дизайн-токенов.

**Нарушения**:
- `#B00508`, `#8A0406`, `#6A0304` - для danger variant
- `#4D4DFF`, `#1A1A80`, `#000066` - для primary/basic-accent variant
- `#D0D9FF`, `#B5C4FF`, `#9AAFFF` - для basic-secondary variant
- `#7A7A7A`, `#5F5F5F`, `#454545` - для basic-gray variant

**Рекомендация**: Добавить эти цвета в `tailwind.config.js` как токены для состояний (hover, active, pressed) или использовать существующие токены, если они подходят.

**Пример исправления**:
```typescript
// В tailwind.config.js добавить:
colors: {
  // ... existing
  'basic-accent-hover': '#4D4DFF',
  'basic-accent-active': '#1A1A80',
  'basic-accent-pressed': '#000066',
  // и т.д.
}
```

### 2. Хардкодные цвета в EyeIcon

**Файл**: `web/src/components/ui/EyeIcon.tsx`

**Проблема**: Используется хардкодный цвет `#949494` вместо токена `basic-gray`.

**Нарушения**:
- Строки 26, 44, 48: `fill="#949494"` и `stroke="#949494"`

**Рекомендация**: Использовать `currentColor` и задавать цвет через className:
```tsx
<path
  d="..."
  fill="currentColor"
  className="text-basic-gray"
/>
```

### 3. Хардкодные цвета в глобальных стилях

**Файл**: `web/src/index.css`

**Проблема**: В body стилях используются цвета, которых нет в дизайн-токенах.

**Нарушения**:
- Строка 79: `background-color: #f7fafc;` - не определен в токенах
- Строка 80: `color: #2d3748;` - не определен в токенах

**Рекомендация**: Использовать токены или добавить их в конфигурацию:
```css
body {
  background-color: var(--background-light); /* или токен из Tailwind */
  color: var(--text-dark); /* или токен из Tailwind */
}
```

## Средние проблемы

### 4. Произвольные размеры шрифтов

**Файлы**: 
- `web/src/pages/Parameters.tsx` (строка 198)
- `web/src/pages/Tokens.tsx` (строка 117)
- `web/src/pages/ProjectDetail.tsx` (строка 175)
- `web/src/pages/Login.tsx` (строка 34)

**Проблема**: Используются произвольные размеры вместо токенов типографики.

**Нарушения**:
- `text-[28px]` - используется в нескольких местах, но не определен как токен
- `text-[96px]` - используется для логотипа

**Рекомендация**: 
1. Добавить `text-heading-28` в `tailwind.config.js` если это стандартный размер
2. Или использовать ближайший существующий токен (`text-heading-32`)
3. Для логотипа можно оставить произвольный размер, но добавить комментарий

**Пример**:
```javascript
// В tailwind.config.js
fontSize: {
  // ... existing
  'heading-28': ['28px', { lineHeight: '100%', fontWeight: '700' }],
}
```

### 5. Произвольные размеры компонентов

**Файл**: `web/src/components/ui/Avatar.tsx`

**Проблема**: Используются произвольные размеры вместо стандартизированных значений.

**Нарушения**:
- `w-[180px] h-[180px]` - для большого аватара

**Рекомендация**: Если это стандартный размер, добавить в spacing tokens или оставить с комментарием о том, что это специфичный размер из дизайна.

### 6. Несоответствие паттернам в некоторых компонентах

**Файл**: `web/src/pages/Projects.tsx`

**Проблема**: Используются нестандартные классы для заголовка.

**Нарушения**:
- Строка 90: `text-heading-32` без `text-text-dark` (хотя это может быть намеренно)

**Рекомендация**: Проверить, что все заголовки используют полный набор классов согласно паттерну:
```tsx
<h1 className="font-istok-web font-bold text-heading-32 text-text-dark">
```

## Мелкие замечания

### 7. Использование произвольных значений spacing

**Файлы**: Множество файлов

**Проблема**: Используются произвольные значения отступов, которые могут быть стандартизированы.

**Примеры**:
- `gap-[72px]`, `gap-[40px]`, `gap-[32px]`, `gap-[24px]`, `gap-[10px]`, `gap-[4px]`
- `px-[120px]`, `px-[16px]`
- `py-[40px]`, `py-[8px]`

**Рекомендация**: Эти значения используются последовательно, что хорошо. Можно рассмотреть добавление часто используемых значений в spacing tokens для лучшей консистентности.

### 8. Комментарии на русском языке

**Замечание**: Комментарии в коде на русском языке, что соответствует правилам проекта. Это не проблема, но стоит отметить для консистентности.
