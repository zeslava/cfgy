## Этап 2.5: Интеграция CLI с сервером ✅

**Цель:** CLI работает с удалённым сервером

- [x] HTTP клиент для работы с API

- [x] Команда `cfgy token list` для просмотра установленного токена

- [x] Модификация команд (`set`, `get`, `list`) для работы с сервером

- [x] Автоматическое определение режима работы (локально/сервер) по наличию `CFGY_API_TOKEN` и `CFGY_SERVER_URL`

- [x] Использование токенов из переменной окружения (токены создаются через веб-дашборд, см. [ARCHITECTURE.md](./ARCHITECTURE.md))

**Результат:** ✅ CLI работает как локально, так и с удалённым сервером

**Использование:**
1. Создать токен в веб-дашборде (см. [ARCHITECTURE.md](./ARCHITECTURE.md))
2. `export CFGY_API_TOKEN=<token>` - установить токен из дашборда
3. `export CFGY_SERVER_URL=http://localhost:8080` - установить URL сервера
4. `cfgy projects create` - создать проект на сервере
5. `cfgy set KEY VALUE --env production` - установить секрет (работает с сервером автоматически)
6. `cfgy get KEY --env production` - получить секрет
7. `cfgy list --env production` - список секретов

**Примечание:** CLI не имеет команды логина и не создает токены. Токены управляются только через веб-дашборд.
